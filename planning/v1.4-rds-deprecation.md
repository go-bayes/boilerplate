# v1.4 RDS deprecation and workflow hardening

Date updated: 2026-07-09

This document records the current `1.4.0` release policy. Earlier drafts on this branch described a warn-on-write transition with full removal deferred to `2.0`; the implementation now takes the safer route for `1.4.0`.

## Current release policy

`1.4.0` removes RDS writing from package APIs. `boilerplate_save()`, `boilerplate_export()`, `boilerplate_init()`, and the internal `write_boilerplate_db()` helper all error when callers request `format = "rds"` or `format = "both"`. `boilerplate_export(output_file = "*.rds")` also errors before creating directories or files.

RDS reading remains available only as a legacy bridge. `boilerplate_import()`, `boilerplate_rds_to_json()`, `boilerplate_migrate_to_json()`, and `compare_rds_json()` can still read trusted legacy RDS files. Every RDS read goes through `read_rds_database()` and emits a real R warning before `readRDS()` deserialises the file. `quiet = TRUE` does not suppress that safety warning.

When JSON and RDS versions of the same database both exist, import prefers JSON. If the ignored RDS file is newer than the JSON file, import emits a warning so users do not silently load stale JSON in a mixed legacy directory.

`boilerplate_batch_edit()` loads JSON file paths only. Legacy RDS files must first pass through `boilerplate_import()` or `boilerplate_migrate_to_json()`, so every RDS read funnels through the warning path.

## Completed work

- `DESCRIPTION` is bumped to `1.4.0`.
- `NEWS.md`, `README.Rmd`, `README.md`, vignettes, generated Rd files, and `cran-comments.md` describe JSON-only writing and the trusted legacy RDS migration path.
- RDS write requests have hard-error tests, including the guarantee that `.rds` export filenames fail before directory creation.
- Legacy RDS read paths have warning tests.
- JSON preference has tests for unified and category databases.
- Newer-RDS shadowing has tests for unified and category databases.
- Incidental RDS writer tests were moved to JSON or to explicit `saveRDS()` fixtures where the test is about legacy migration.

## Follow-up hardening for 1.4.x

These items do not block `1.4.0`.

1. Add a trusted-root or explicit-consent gate for RDS reads in `boilerplate_import()`.
2. Make copy and backup operations symlink-safe.
3. Restrict bibliography downloads to safe URL schemes.
4. Add download size/time limits.
5. Add conservative size/depth limits for JSON parsing.

## Longer-term RDS removal

After a transition period, remove RDS reading from general import paths. Keep a clearly named migration-only path if users still need a one-way conversion tool for old databases.
